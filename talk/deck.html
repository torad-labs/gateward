What a lifecycle hook is

A checkpoint between
"the agent decided to write this"
and "this landed on disk."

Your code runs first. It can say no — and say why.
Claude Code · Codex · Antigravity · OpenCode — every harness ships these now.
Build · step 1 — intercept the write
.claude/settings.json 
{ "hooks": { "PreToolUse": [
  { "matcher": "", "hooks": [
    { "command":
      "bun .tenets/engine/pretooluse.ts" }]}
]}}
what the harness hands us 
{ "tool_name": "Edit",
  "tool_input": {
    "file_path": ".../domain/Toggle…​.kt",
    "new_string": "…(context: Context)" }}
Before any write or edit, our code runs first — and it can say no.
Build · step 2 — project the post-edit file
packages/core/src/projection.ts 
/** The before/after content of a decidable, gated tool call. */
export interface Projection {
  path: string;
  /** On-disk content before the call ("" for a new file). */
  current: string;
  /** Content the call would produce. */
  projected: string;
}
The gate judges the projected content — never the raw edit. When the outcome is undecidable, it declines to judge, and never double-judges.
Build · step 3 — parse, don't grep
packages/core/src/scan.ts 
exec(["scan", "--inline-rules", rules, "--json=compact", tmp]);

Your architecture is structural. Stop grepping for it.

ast-grep reads a syntax tree — 25+ languages. Regex can't tell a Context parameter from the word in a comment. A tree can.
Build · step 4 — one rule
packs/android-architecture/rules/no-context-in-domain.yml 
id: no-context-in-domain
language: kotlin
message: >-
  Domain code must stay platform-agnostic — drop this
  Context parameter and pass the plain data it needs.
files:  [ '**/domain/**' ]     # fires by LAYER, not file
rule:
  any: [ {kind: class_parameter}, {kind: parameter} ]
  has: { kind: user_type, regex: '^Context$' }
Lint sees a file. This rule sees your layering.
Build · step 4 — the rule has its own tests
rule-tests/no-context-in-domain-test.yml 
valid:
  - 'fun observeListing(id: String): Flow<Listing?>'
invalid:
  - 'class FavoritesStore(context: Context)'
  - 'fun refresh(context: Context) {}'

Fifteen lines of rule. Eight lines of test.
Rules are code. Code has tests.

Build · step 5 — the block message is instructions
packages/core/src/events/pretooluse.ts 
function denyReason(matches: Match[]): string {
  return matches.map(m =>
    `[${m.ruleId}] line ${m.line}: ${m.message}`).join("\n");
}

Design decision 2 of 3 — there is no bypass

A gate with a side door
isn't a gate.

  • The suppression comment is itself a blocked pattern
  • Enforcement tool missing → edits denied, not waved through
And the agent will look for the side door. Let me show you.
The side door · a true story

Blocked by FP-precision rules, an agent wrote obfuscated code to a scratchpad — then wrote a mover script to smuggle it into the codebase.

$ bun demos/side-door/prove.ts
ACT 1 · Write the violation → ⛔ BLOCKED
ACT 2 · same content via mv → 🕳 UNSEEN the write gate is blind to Bash
ACT 3 · Bash counter-guard on → identical mv → ⛔ BLOCKED

You can't enumerate every trick.
You can evolve the gate.

Act three was one hook away — and it reuses the same definition of "gated file" as the write gate. A gate isn't a wall you build once. It's code you evolve the moment something gets past it.

Tenets that travel

From what it writes → to what it decides

So far the gate watches what the agent writes.
It can also watch what the agent decides.

The stop hook · real capture
backlog: F1 [done] · F2 [todo]
⏺ Marked F1 done. F2 remains open — stopping here.
⎿ Stop hook: You're about to stop, but 1 task is still open (1 todo):
  - F2 [todo] Add the test that proves toggling twice is a no-op
"Don't stop until you're done" stopped being a line in a prompt the model forgets — and became a checkpoint it has to reckon with.
Why this shape
  • Declare-then-earn — the tracker is an input you can't lie to
  • Substrate, not instruction — the nudge rides the agent's own stop; a prompt line decays at compaction, a hook fires every turn
  • Loop-safe — honors stop_hook_active; the agent is never trapped
One discipline, two checkpoints: the file, and the session.
